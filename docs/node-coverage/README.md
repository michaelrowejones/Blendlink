# Native Blender node coverage

Generated by `scripts/audit-node-coverage.py`; the native catalogs record actual node creation, context-valid enum values and deduplicated socket schemas.

**Supported** means an explicit compiler/extractor and runtime implementation within the stated limits; it is not whole-scene pixel parity. **Partial** has missing modes, outputs or parameter domains. **Bake-only** is a deliberate static native evaluation route and is never counted as live translation. **Structural** is graph traversal/editor structure. **Unsupported** has no audited live route.

Every registered Node subclass is attempted, without ShaderNode/CompositorNode prefix filtering. This includes shared FunctionNode/GeometryNode utilities and internal/editor/closure/bundle types where actual context creation succeeds; it is not an Add-menu or asset-group count. Python class poll can incorrectly exclude usable shared nodes.

Live material programs require `WebGPURenderer` (WebGPU or its WebGL2 backend), not legacy `WebGLRenderer`. Compositor programs use the same node renderer; whole reachable graphs build or refuse. Animated/driven node parameters, graph cycles, unmodeled socket conversions, unsupported render passes and renderer-specific lighting impose additional limits. Node/menu coverage is not a guarantee that every arbitrary graph combination is representable.

Counts are node **types**, not node instances or percentages of all shader looks. Shader and compositor contexts are separate; shared types are inventoried in each context where they can actually be created. RNA values rejected by assignment (for example geometry-only Mix Rotation in a shader tree) are excluded from available mode counts.

## Remaining work by batch

- **1. Common compositor pointwise graph operations**: Port newly discovered shared typed utilities: Boolean/Integer/Compare inputs and math, menu/switch handling, vector/rotation/matrix operations, strings and graph composition. Function/Geometry class names alone do not imply shading support.
- **2. Close modes and parameter domains of existing live nodes**: Remaining shader color modes, image sampling/projection/alpha domains, generated/GPU object-instance metadata and color/index property timelines; finish unsupported native GPU filter models and remaining parameter restrictions.
- **3. Procedural textures and coordinate/geometry inputs**: Gabor/Sky/IES, remaining Noise/Voronoi features and scale bands, vector transforms/tangents/geometry attributes and bump/displacement conventions; distinguish exact, bounded approximation and static capture.
- **4. Spatial compositor and render-pass pipeline**: Additional Blur/Glare kernels, transforms/crop/scale, masks, dilation/erosion, lens distortion, defocus/vector blur, denoise, multilayer/AOV/cryptomatte sources. These need image-domain sampling, buffers or temporal integration, not class-name aliases.
- **5. Full surface/light/volume behavior**: Additional BSDFs, anisotropy/subsurface/hair/volumes, ray queries and Blender 5.3 light-evaluation nodes; preserve lighting/geometry dependencies and state explicitly where browser rendering cannot reproduce native path-traced semantics.
- **6. Time, file/media, color-management and graph execution**: Driven/animated graph parameters, image/movie/sequence inputs, OSL/custom nodes, OCIO conversions and full graph combinations; add dependency tracking, lifecycle, diagnostics and versioned evidence before calling them live supported.

These batches are a coverage roadmap, not evidence that the listed nodes have been ported. Preserve explicit refusals or declared bake paths until native/compiler/runtime and numeric differential evidence agree.

## Regenerate and check

```sh
python3 scripts/audit-node-coverage.py --blender /path/to/blender-4.2 --blender /path/to/blender-5.3 --check
python3 scripts/audit-node-coverage.py --self-test
```

`--update-baseline` acknowledges observed native availability and schemas only; it never promotes support. New node types or enum values, changed socket schemas and changed boolean defaults fail `--check` until reviewed. New types also need an explicit capability entry or an acknowledged `knownUnsupported` entry; live routes need explicit enum rules. Source hashes and evidence anchors expose stale capability claims. Enumerated menu/property schemas are single-setting probes, not exhaustive setting cross-products.
