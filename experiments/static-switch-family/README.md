# Static Switch family: Blender 5.3

`GeometryNodeSwitch`, `GeometryNodeIndexSwitch`, and `GeometryNodeMenuSwitch` can select a supported shader/compositor branch at export time. The authored selector must be a fixed correctly typed Boolean/Integer/Menu value. Literal group bindings, typed Bool/Int nodes, resolved native `FunctionNodeInputMenu.value` sources, reroutes, native mute bypass, nested static selections and fixed Boolean Math are bounded. Only the chosen branch enters emission and dependency planning; an unsupported inactive artist branch does not force baking. Menu's Boolean selection masks fold to typed constants. This is compile-time graph selection and adds no GPU operation, material, texture or render pass.

Five data types are measured: FLOAT, INT, BOOLEAN, VECTOR and RGBA. Selected fields use their existing upstream implementation; the shader field oracle uses authored SNAP-quantized UV, while compositor field cases use actual Render Layers. Shader closures, other data types, dynamic/implicitly converted selectors, animation/drivers/NLA, invalid Index, ambiguous Menu labels, over 32 branches, cycles and over-budget traversal remain named refusals. Source/build guard is 5.3.0 `02f0899d78e3`; other builds remain unqualified. This does not claim a general dynamic branch runtime.

The source implementation follows pinned Blender shader inlining and compositor forwarding (`sources.json`). Three native contexts are separate: EEVEE shader, compositor CPU, compositor GPU. Native renders read full 32-bit EXR pixels; authored saved `.blend` bytes are unchanged. A temporary shader Emission oracle measures the same Base Color expression, then restores the Principled graph. Saved Final exports contain the actual selected material IR or compositor program, checked against native-emitted programs. Browser shader checks measure the actual installed Base Color channel, rather than claiming whole-material lighting parity. Final compositor checks use the actual published glTF, source presentation, binding and post-pipeline.

Run with Node 24 after an isolated `npm run build`:

```sh
SCENETOWEB_SWITCH_EVIDENCE=artifacts/verification-switch-fresh \
  node experiments/static-switch-family/suite.mjs --built
```

The guarded native transaction refuses an existing qualification and uses bounded subprocess argv without a shell. The suite records step timings and retains failing logs. Every qualification owns fresh native and Final calls through the proof launcher, including nested SDK exports via `BLENDLINK_BLENDER`. Each Python action receives a fresh cache prefix before staged imports. Invocation identities, unique prefixes, cleanup and exact saved-source coverage are archived before launcher disposal and independently checked by the closed reader. Existing project caches are never deleted. Every native helper/source, program, pixel, saved scene, publication, immutable built runtime snapshot, vendor module and closed case census is rechecked. `verify.mjs` closes all 12 browser receipts (3 contexts ×2 adapters ×raw/Final), each containing actual WebGPU and WebGL 2. Missing WebGPU adapters must refuse. Metal/SwiftShader identities must be actual. Every compared Float32 word, shader/API error, owned texture, source restoration and invalid-publication-pin check must pass.

The added native Menu sources cover direct, reroute and artist-group paths for both resolved choices. Empty/unresolved native Menu choices refuse; the node output socket default does not substitute for the resolved native node storage value. Controls, private probes, class creation and N/A get zero coverage credit. `evidence.json` is the compact local receipt; raw artifacts remain ignored. `capability-proposal.json` is for root integration, not the capability registry itself.

## Mono Switch View variant (qualified next20r4)

`--mono-view` selects a separate eight-source CPU-only variant while preserving the default71-case, three-context selector suite. It reuses the same built runtime capture, browser/Final installer, exporter and closing reader. The new source definitions are in `view-cases.json`, with one shared `view_cases.py` builder. All eight sources are saved and published through actual Final exports: calibration, literal, disabled/renamed actual first input, inactive Scene Time, group/reroute, varying packed byte-PNG Image, and RenderLayers→ImageInfo identity domain. The native0×0 single-value domain diagnostic remains separate; this variant does not admit single-value ImageInfo.

```sh
SCENETOWEB_SWITCH_EVIDENCE=artifacts/verification-NEW-mono-view node experiments/static-switch-family/suite.mjs --built --mono-view
```

The fresh [closed mono receipt](../compositor-switch-view/evidence.json) records eight total native graphs and saved Final scenes (one calibration plus seven SwitchView sources), 64 total raw/Final browser case-runs (56 actual SwitchView), 16,384 total primary words (14,336 actual SwitchView), zero differences, and ten guarded native Python invocations. Calibration receives no node coverage. Each browser tuple independently calibrates physical Float32 readback orientation before using the port. Both APIs and observed Metal/SwiftShader profiles must pass exact words, publication-pin refusal, resource cleanup and source-material ownership restoration; Final repeats installation/disposal. The closing reader validates selected-view annotations, excludes inactive SceneTime dependencies, compares actual saved Final presentations with native source programs, and independently emits the runtime again. A shared compiler transaction is explicit and pinned; there is no automatic numerical reuse.

No shader kernel, texture or pass is introduced by SwitchView selection itself. The selected expression inherits its existing source/runtime contract; the varying image uses its already-qualified packed sRGB PNG transport with asymmetric exact binary0/1 channels and alpha1. Raw native pixel reads are checked after loading and before packing/saving. The first next19 transaction retained a named refusal for packed float EXR display windows; it grants no full-matrix qualification. Its fresh successor uses the already-admitted byte image path, with no Image admission, tolerance or output repair change. Stereo/named live views, GPU-authored compositor sources, source Scene/tree animation or drivers, unknown schemas and over-budget chains remain refused. Source Scene ID animation is conservatively excluded because native `render.use_multiview` is animatable. Exact input0 selection does not infer a hidden Scene owner or hardcode a left-view name.

The fresh next19r2 transaction captured all eight native frames and saved sources, then stopped before qualification publication because the inherited GPU renderer-name query requires an initialized GPU context. The mono CPU variant now records explicit native CPU evaluation, `gpuInitialized=false` and no GPU credit; it does not warm or initialize a GPU for metadata. The original three-context reference keeps its existing actual GPU query. Failed r2 artifacts remain separate; a fresh r3 transaction is required.

The next19r3 transaction closed eight native captures and actual saved Final publication, then failed the raw RenderLayers calibration: its one-sample Cycles carrier produced 64 distinct RGB tuples, while the inherited raw resolver correctly supplied the declared flat source. Read-only inspection confirmed CPU, one sample, denoising/adaptive sampling enabled and a valid Emission→Surface link. This fixture does not establish Cycles/Three material equality. The mono variant now authors a literal compositor calibration and asserts its exact predeclared words before any view capture; the independent GPU orientation control stays unchanged. A new diagnostic namespace retained one fresh CPU literal render and all eight raw cases on both actual Metal APIs, using seven immutable r3 rows and an explicitly pinned r3 runtime snapshot with zero qualification credit. At that diagnostic checkpoint a new complete transaction was still required; next20r4 subsequently closed the full qualification. The original selector variant and its original evidence are unchanged.
