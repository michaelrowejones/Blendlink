# CPU fixed-axis Vector Rotate experiment

This is an isolated pilot, with zero support or saved Final credit. The candidate accepts fixed X/Y/Z modes, either Invert value, bounded literal controls and either a literal Vector or the private exact Normalized-coordinate consumer. Existing shader Vector Rotate, the standalone Normalized profile and Displace precision functions are unchanged.

The frozen plan contains 22 cases. It covers all three axes and Invert settings at ordinary and minimum Angle, literal bounds, grouped/rerouted coordinates, odd/portrait/DPR extents and both maximum-thin orientations. Five independent native integer Pixel controls establish file/domain orientation. Native CPU references retain the original Render Layers and math nodes; no image replacement or output repair is used. Every output has pre-store native Float Hash witnesses carried through exact low/high 16-bit CPU channels.

The browser uses built runtime snapshots and a genuine borrowed FRAME PassNode. An unrelated raw texel-copy calibration and native Pixel/screen-coordinate comparison run before rotation comparisons. Every output word must match exactly. Warm upload counts, producer entry state, replaced-producer refusal, invalid-extent recovery and saved renderer disposal are checked. The port owns one R32F two-row table for field inputs, at most 64 KiB of data, and no render target; the fixture separately owns the input PassNode and readback target. This is not a whole-scene lighting or native shader proof.

The native transaction closed 22 cases, 71 renders and 400,587 pre-store component hash checks without differences. The first four browser tuples passed their numerical checks, but the runner accidentally removed numeric word counts when serializing raw samples. Those original records remain unmodified and unclosed. Three regression tests cover the corrected serializer. Fresh `browser-r2-*` transactions then passed, and an independent reader rederived all 4,272,928 rotation words and 1,059,808 orientation-control words without differences. The four saved-renderer disposal controls each retired the original owned row handle exactly once. Current independent runtime emission, raw binary comparisons, native launcher archive, vendor bytes and fixture snapshots close separately. The SDK and exact-word gates were unchanged.

`matrix.mjs` runs fresh guarded native references, actual built Final publication, both actual APIs on Metal and SwiftShader, and the independent reader. The raw and public Final browser routes retain all linear readback words; numerical failure snapshots are written before the page closes. Final tests use `startThreeCompiledScenePreparation(...).promise.commit()`, cancellation, uncommitted disposal, three install cycles, caller-owned scene/material/callback restoration, and the actual installed compositor node for exact pre-display projection. The source scope remains fixed X/Y/Z only, both Invert values, Angle positive zero or a normal Float32 magnitude from `2^-16` through `1`; Center/literal Vector positive zero or normal magnitude from `2^-16` through `16`. The varying route is only direct qualified Normalized coordinates from the original current-scene full-frame Render Layers, with private exact rows.
