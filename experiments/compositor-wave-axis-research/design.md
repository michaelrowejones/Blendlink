Proposed live Wave axis port
===========================

Implement an artist-useful compositor field, rather than another literal-only function. Initial source scope is pinned Blender 5.3 CPU compositor FULL/AUTO, implicit Uniform Vector, Bands X/Y, Distortion raw positive zero, static literal Scale/Phase and Color/Factor outputs. Preserve the original default Scale 5 and Phase 0. SAW/TRI target exact Float32 words. The SIN proposal failed its unchanged endpoint gate in the extended native corpus and remains unqualified, including the default SIN profile; reproducing Apple libm is deferred. No profile is admitted until fresh native, saved Final and actual browser proof closes.

The initial proposed parameter domain is Scale/Phase positive zero or finite normal Float32 with nonzero magnitude at least 2^-16 and absolute value at most 8. Signed boundary and adjacent-Phase seam controls now pass exactly for SAW/TRI in the finite native research census. This range still has **not** earned production qualification or a universal-domain proof; fresh closed source/runtime controls must precede admission. Read stored scalar words through the reviewed public native-copy reader, before Python promotion. Refuse negative zero, subnormals, fields/computed controls, linked Vector, animation/drivers/NLA, nonidentity source settings without a native model, render borders and nonsquare pixels. Do not walk dead fractal dependencies when Distortion is exactly zero. Source and runtime must agree on the exact keys, native socket identifiers, model/profile, raw static parameters, frame/domain metadata and fixed budgets.

CPU staging is owned by a new Wave evaluator, not an EEVEE label. Its small per-axis table computes the mathematical function on the browser host for each native coordinate when the physical extent changes. This is a live function implementation, not rendering or baking the authored scene. Native evaluation remains an independent oracle; the browser must not invoke Blender, evaluate an arbitrary user graph or reuse saved output pixels. SIN differences remain visible in receipts. No output clipping, seam epsilon or input quantization is permitted.

Shared resource seam
--------------------

Wait for the White Noise qualification scaffold and production fixes to freeze and close. Its owner reports frozen production at `82d883f`, with first-draw allocation and saved-dispose controls still requiring the full proof. Do not change that candidate during its proof.

After closure, extract only its owned R32F allocation/lifecycle machinery into an internal `OwnedCompositorRowTable` helper. Preserve the actual physical renderer/target/mip/DPR checks, immutable texture schema, captured GPU allocation, partial-initialization cleanup, weak device-loss callback and saved-original-dispose fallback. White Noise retains a separate two-row coordinate builder and opaque owner test. Wave retains a separate one-row factor builder and opaque source model. The helper does not interpret source JSON or grant source admission.

Prefer one table per distinct Wave axis/profile/Scale-word/Phase-word key, shared between that node's Factor and Color outputs and identical sources in the same compositor build. Avoid a new dynamic packed-row allocator in this batch. Each table holds one row whose width is at most the maximum physical extent; unused padding is deterministic. At maximum extent 8192, one Wave factor row costs at most 32 KiB of Float32 CPU data and 32 KiB of logical GPU texels. Physical GPU allocation bytes require separate measurement. The existing White Noise two-row table remains separately counted. Use a single valid extent entry per owner; replace it only after all computations and validations succeed. Do not cache all historical resize sizes.

The construction-time evaluator callback must come from reviewed internal builders, never from a caller-supplied source annotation. A live draw keeps the guard callback reachable even if downstream math produces a constant. Warm frames perform constant-time schema/identity checks, without rescanning row buffers. A valid physical extent/settings change computes and uploads one replacement row; invalid extents preserve the last valid cache and allocation. No new render target, pass, readback or per-frame native evaluation is needed by the helper itself. Whole Final installation costs must still be measured against its actual baseline.

First proof matrix
------------------

Start with an actual CPU staging pilot before any renderer work. Extend the research settings to both parameter bounds, zero Scale, positive/negative Phase, cancellation, quotient seams and Float32 predecessor/successor controls. Add an explicit native-one SIN control; the current SIN corpus contains only native-zero endpoint controls. Preserve original default values. Then freeze source/runtime/fixtures once and run fresh native references, exact source/recipe preflight, saved actual Final publications and both actual APIs on Metal and SwiftShader.
