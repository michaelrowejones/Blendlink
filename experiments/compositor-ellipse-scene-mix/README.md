# Binary Ellipse compositing over the current Three frame

The closed admission reader qualifies exact linear composition on the observed Metal WebGPU/WebGL2 tuples. Eight saved Final sources and64 native image oracles/192 actual CPU renders produced32 credited Metal cases,37,440 exact direct words and224,640 exact installed-Final linear words across96 apply/dispose cycles. Both SwiftShader APIs named-refuse decoder calibration and receive zero numerical/support credit for this extension. `evidence.json` preserves the exact closed reader output; existing standalone Ellipse and generic Mix receipts remain unchanged.

The source is deliberately small: one direct RenderLayers **Image or Alpha** from the current Blender scene and exported view layer, one CPU-qualified axis-aligned Ellipse with Add/Mask0/Value1, and one terminal modern Color/MIX. Either Mix side may contain the scene value. The other side must be an unlinked native RGBA literal whose raw components are positive zero or positive normal F32 values at most one. Source and runtime independently validate the complete three-op graph. The inner Ellipse builder retains that complete graph; an operation-list-only call cannot acquire a scene-input exemption.

The runtime owns one current-frame, full-size HalfFloat RGBA ScenePass with MSAA0 and integer physical-texel loading. Image sampling has no interpolation or offset. It requires a device/context-specific decoder certificate before installation; unknown decoders named-refuse. Other image producers, arbitrary scene/view-layer references, extra shader chains, Alpha Over, and additional registered pre-HDR/post-LDR effects remain outside this extension. There is one varying row table. Scene image1 + row1 + display lookups must total at most eight samplers. This is a useful scene-mask composition slice; it is not general Blender compositing or a proof that Three PBR matches Cycles.

## Arithmetic, ownership and cost

A GPU endpoint selection is insufficient even for exact binary factors. Native CPU Mix evaluates `(1-f)*A + f*B`, including zero-weight exceptional operands. The source-pinned, bit-classified binary implementation reproduces the bounded native zero, infinity and NaN rules without evaluating GPU floating Mix algebra. The retained exhaustive HalfFloat prototype covers all 65,536 uploaded encodings in each RGBA channel, both factors and both operand directions on both observed APIs: 3,145,728 words, zero differences. Actual decoded GPU words—not a NumPy HalfFloat decoder—were supplied to native CPU Image references. Separate signed/payload F32 NaN controls and actual rendered ScenePass attachment controls are retained as pilot observations; they do not replace this family's integrated Final proof.

Decoder calibration runs once per actual renderer/device/context allocation epoch. Concurrent preparations share it; cancellation detaches a caller. Its temporary draw/readback state is restored before waiting, allowing an existing pipeline to keep rendering. Owned texture, target, framebuffer, fence and staging allocations close on success, failure, cancellation completion, context/device loss and renderer disposal. A previously saved original dispose is detected by the allocation epoch; captured physical handles supply cleanup if the old manager was reset. Replacing an intact manager preserves its original disposal ownership. The cache contains no calibration GPU resources after completion. No per-frame readback or payload `finiteScene` flag exists.

Nominal transient calibration storage is 4 MiB, excluding driver/compiler caches and implementation overhead. Observed pilot calibration was about 133 ms WebGPU / 67 ms WebGL2 with cold driver shader caches, and 11 / 14 ms on a later run with those caches warm. These are local observations, not steady-state rendering or export-latency measurements. Warm certificate reuse submits no calibration draw. The existing Ellipse row table remains fixed at 64 KiB; per-frame boundary preparation is O(W + H log W), with no CPU full-pixel mask generation. The scene color attachment is an ordinary full-frame HalfFloat image; this feature does not remove scene rendering cost.

## Independent proof stages

Eight original saved scenes cover Image/Alpha, both operand sides, and dyadic, positive-zero or minimum-normal backgrounds. Both APIs and Metal/SwiftShader profiles use physical 13×9/DPR1 and 18×26/DPR2 frames. Each baseline must contain actual visible RGB and fractional alpha.

1. Save owned Blender sources and record their exact three-op programs. Publish those unchanged `.blend` files through the built Final exporter, preserving source/program/GLB/manifest/presentation hashes.
2. Load the actual published GLB and independently render its Three ScenePass at the same HalfFloat/MSAA0 precision. Record the actual F32 frame bytes separately for every API/profile/extent. This stage does not use the port's mask, binary Mix or frame-binding code.
3. Feed those exact bytes to an owned native CPU compositor Image oracle, leaving the original saved RenderLayers graphs untouched. Independently copy-check the image/EXR path, then capture actual native Ellipse→Mix words. A separately labelled source-derived CPU display witness uses the pinned Blender wrapper's reciprocal→multiply→identity-OCIO→multiply staging. The actual identity PyOpenColorIO CPU processor is called and asserted no-op; this is not a direct call to Blender's C++ display wrapper. The older component-division ToStraight witness remains a separate diagnostic.
4. Reload/redraw the saved scene and require an identical independent baseline. Require exact native words for both the direct production compositor and the **actual installed Final pipeline's pre-display compositor node**, sampled only by the proof into an owned Float32 target after each actual Final render. Raw display is a separate audit: record all word differences, maximum ULP, unclamped absolute error, and clamped absolute error, with exact alpha and nonfinite classes; finite zero/underflow differences are counted and exemplified. Its finite RGB projection gate reuses the pre-existing `experiments/eevee-look-differential/README.md` OCIO/PNG clamp-to-[0,1] maximum absolute error3e-5; it is not a new four-ULP theorem or a bit-exact display promise. Repeat exact linear sampling and audit across three installation/disposal cycles. Capture the texture identity baseline before allocating the direct port; direct cleanup and every pipeline cycle must return to that baseline and preserve source materials/callbacks.
5. Independently validate source/runtime/fixture/vendor hashes, exact case and API/profile census, raw native bytes, both stage-specific native archives, and a fresh whole-program runtime emission. A failed stage cannot become a qualification by editing a receipt.

The original sources are preserved; the numerical reference substitution happens only in the owned oracle. Raw display is required to have an actual empty native OCIO operation list. Other views may fit the production sampler budget but this experiment does not independently qualify every view. No original demo acceptance or new material/lighting/node port is claimed.

## Pinned display boundary

`raw-display-sources.json` records full02f0899d78e374b63e7181d9061e1f7ab03419cc primary URLs, SHA-256 values and line ranges. CPU `LibOCIOCPUProcessor::apply_predivide` uses rounded reciprocal multiplication for nonzero/non-one alpha even when the OCIO processor itself is identity. The GPU display shader has its own predivide range and conditional premultiplication. Empty OCIO operations alone therefore do not prove a word-exact native CPU display no-op. The corrected witness is explicitly source-derived/native-operator staging plus an actual identity OCIO CPU call, not an actual Blender C++/GPU display invocation. The final evidence must keep that distinction and record measured display deltas; exact linear compositor credit does not promote the global display implementation.

The `next11r4` display audit also retained a finite-underflow failure: minimum-normal RGB became zero in the shared GPU display path, with unchanged alpha/nonfinite classes and absolute error1.17549435e-38. Its zero-bit restriction exceeded the pre-existing clamped display projection contract. The subsequent contract removes only that extra display zero-bit gate, records actual zero-direction counts/examples and keeps all direct/installed linear words exact. The closing reader recomputes display acceptance from numeric metrics and validates repeated/installed/audit word census. No production pixel repair or global display promotion is made.
